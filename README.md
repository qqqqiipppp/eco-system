# 작은 숲 연구소 — 생태계 관리 행동

기존 카드 선택 → 숲 터치 → 배치 → 먹이 탐색/섭식 흐름을 유지하면서 햇빛·물·공기·토양과 생태계 안정도를 연결했습니다.

## 5단계 관찰 이벤트

실제 먹이 부족에는 !, 식물 성장 저하 조사에는 ?, 첫 먹이 관계 발견에는 💡가 나타납니다. 표시를 터치해 살펴보고 **발견 기록하기**로 기록하세요. 상단 발견 기록에서 확인할 수 있으며 새로고침하면 초기화됩니다. 최대 4개 표시, 중복 방지, 조건 해소 시 종료와 재알림 대기 시간을 적용했습니다. 발견 기록과 조사 정답은 최초 보상을 줍니다.

## 6단계 관리 행동

? 조사 정답으로 최초 10포인트, 💡 먹이 관계 기록으로 최초 12포인트를 얻습니다. !를 열고 살펴본 뒤 상황에 맞는 관리 행동을 고르세요. 처음 포인트는 0이며 단순 열람에는 보상하지 않습니다.

- 물 환경 개선/토양 돌보기: 6포인트, 한 단계 개선. 기존 생산자 회복에 반영됩니다.
- 임시 먹이 지원: 5포인트, 한 소비자의 배고픔을 잠시 덜어줍니다. 개체별 45초 대기, 원래 먹이가 없으면 재발합니다.
- 서식지 회복: 8포인트, 60초 동안 식물 성장·먹이 회복을 1.35배 돕습니다. 배고픔을 즉시 해결하지 않습니다.

물/토양의 실제 문제 해결에는 요소별 최초 3포인트를 줍니다. 포인트는 경쟁 점수가 아니라 돌봄에 쓰는 자원입니다. 보상은 의미별 한 번이며 자동 반복 지급하지 않습니다. 환경 창에서 서식지 회복 중인지 확인할 수 있습니다. 기록/포인트는 새로고침하면 초기화됩니다.

## 사용

오른쪽 위 **현재 환경 상태**를 누르면 환경 살펴보기가 열립니다. 네 요소를 좋음/보통/나쁨으로 바꾸고 닫은 뒤 숲을 관찰하세요. 이는 조건 비교용 조작이며 자동 기후 변화나 보전 활동은 아닙니다.

- 햇빛·물 부족과 나쁜 토양/공기: 식물 성장과 풀의 먹이 회복 감소.
- 나쁜 공기: 동물의 이동/먹이 접근 속도 감소.
- 식물의 성장량 감소: 풀의 먹이 보유 한도 감소 → 메뚜기의 섭식 기회 감소 → 먹이 관계에 영향.
- 좋은 환경으로 복구: 식물 성장량과 먹이 공급이 서서히 회복.

식물은 자동으로 죽거나 삭제되지 않습니다. 생산자 감소는 이번 단계에서 성장량/먹이 공급량의 감소로 표현합니다. 상수리나무는 풀보다 토양 영향을 크게 받습니다. 기존 이미지를 작게 표시하는 효과만 추가했으며 신규 이미지가 없습니다.

안정도는 생물 수만이 아니라 다양성, 생산자/소비자/분해자 구성, 먹이 공급과 섭식 상태, 환경, 종별 편중과 최근 감소를 함께 평가합니다. 학생에게는 게이지와 쉬운 문장만 보여주고 내부 항목 점수와 환경 수치는 숨깁니다. 환경 창에 현재 살펴볼 점을 표시합니다.

## 실행과 검사

설치/빌드 없이 정적 HTTP 서버 또는 GitHub Pages에서 실행합니다. 이 폴더에서 `python -m http.server 8080`을 실행하면 `http://localhost:8080`에서 볼 수 있습니다. file:// 더블클릭은 ES 모듈 때문에 지원하지 않습니다. Pages에는 이 폴더 내용을 저장소 루트 또는 docs에 넣으세요. 모든 앱 경로는 상대경로이며 실제 업로드/배포는 하지 않았습니다.

순수 검사: `node --test tests/logic.test.mjs tests/feeding.test.mjs tests/environment.test.mjs tests/events.test.mjs tests/management.test.mjs`

브라우저 검사: 기존 `tests/browser.test.cjs`, 섭식 `tests/feeding.browser.test.cjs`, 환경 `tests/environment.browser.test.cjs`, 이벤트 `tests/events.browser.test.cjs`, 관리 `tests/management.browser.test.cjs`. 정적 서버와 Playwright/Edge가 필요하며 앱 자체에는 검사 도구가 필요하지 않습니다. PLAYWRIGHT_MODULE로 설치 경로, BASE_URL로 주소를 지정합니다.

## 유지 사항

카드 6종, 30개 제한, 기본 배치 검증, 정규화 좌표, 토끼 단순 이동, 풀 → 메뚜기 → 개구리 관계를 유지합니다. 저장/서버/번식/자연 사망/분해/환경오염/별도 퀴즈 시스템은 없습니다. 이벤트 안에는 간단한 원인 판단 질문이 있습니다. 포인트는 시스템을 통해 획득하고 관리에 사용합니다. 새로고침하면 초기 상태로 돌아갑니다.

문서가 숨겨지거나 움직임 줄이기 설정이면 기존 정책대로 이동과 상태 갱신을 멈춥니다. 실제 Galaxy Tab S5e 성능은 실기기 확인이 필요합니다. 예전 STAGE2_REPORT.md와 STAGE3_REPORT.md는 이전 단계 기록입니다. 현재 설계는 ARCHITECTURE.md, 이번 변경 보고는 STAGE6_REPORT.md, 검증 결과는 QA.md를 확인하세요.
