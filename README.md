# 작은 숲 연구소 — 목적 안내와 숲 돌보기

초등학교 4학년 생물과 환경을 위한 싱글플레이 정적 웹게임입니다. 카드를 많이 모으는 것이 아니라, 관찰하고 배운 내용을 적용해 숲을 안정적으로 운영하는 것이 목표입니다.

## 숲 목표

화면 아래 **숲 생태계 목표 · n/6개 달성**에서 요약을 보고 **목표 자세히 보기**를 누르면 현재 달성 여부와 부족한 조건을 확인할 수 있습니다. 다음 조건을 모두 만족한 채 활성 게임 시간 30초를 유지하면 숲 목표를 달성합니다.

- 기존 생태계 안정도 70 이상.
- 햇빛·물·공기·토양 모두 보통 이상.
- 풀 → 메뚜기, 메뚜기 → 개구리 두 관계를 실제 💡 발견 기록에 남김.
- 생산자 퀴즈, 분해자 분류, 풀·메뚜기 관찰 활동 완료.
- 지금 숲에 풀·메뚜기·개구리가 함께 존재.

조건이 깨지면 유지 시간은 처음부터 시작합니다. 새로 불러올 때에도 미완료 유지 시간은 새로 확인합니다. 클리어 기록은 한 번 달성하면 보존되며 이후에도 배치·관찰·관리·학습을 계속할 수 있습니다. 버섯의 실제 분해 기능을 목표 조건으로 요구하지 않습니다.

학생 화면에서는 위 다섯 조건과 마지막 30초 유지를 여섯 목표로 묶어 표시합니다. 실제 판정은 기존 설정을 그대로 사용합니다. 30초는 현재 6종 프로토타입의 임시 값입니다.

## 처음 시작하기

새 게임은 짧은 목적 안내 뒤 카드 선택 → 숲 터치 → 관찰 → 💡 기록 → ! 관리 순서를 보여줍니다. 안내는 건너뛸 수 있고 상단 **도움말**에서 다시 볼 수 있습니다. 유효한 기존 저장을 불러오면 안내가 자동으로 열리지 않습니다.

게임 목표는 안정적인 숲 운영, 학습 목표는 생물·비생물 요소와 생산자·소비자·분해자·먹이 관계 이해입니다. 화면의 **다음 행동**은 실제 배치·발견·활동·해금·환경·안정도 상태에서 한 가지를 추천합니다.

## 플레이 흐름

처음에는 상수리나무·풀·메뚜기를 배치할 수 있습니다. 카드를 고르고 숲을 터치하세요. 최대 30개체입니다.

- 풀을 먹는 메뚜기를 관찰하고 💡에서 기록하면 기존 12포인트를 받습니다. 잠긴 개구리 카드의 관찰 활동을 완료해 다음 먹이 관계를 열어 보세요.
- 이 숲에서 죽은 나무를 분해하는 버섯의 역할을 분류하면 버섯 카드가 열립니다. 모든 버섯의 생활 방식이 같다는 뜻은 아닙니다.
- 생산자 2종·풀·환경 보통 이상·숲의 균형을 갖추면 토끼 카드의 서식 활동을 완료할 수 있습니다. 해금한 생물은 직접 배치합니다.
- 배움에서 퀴즈와 활동을 다시 볼 수 있습니다. 오답은 단서 후 재선택하며 최초 보상은 한 번입니다.
- 현재 환경 상태는 좋음/보통/나쁨으로 관찰합니다. 학생 화면에는 무료 환경 변경 버튼·선택창이 없습니다. !의 설명을 읽은 뒤 물/토양 개선·임시 먹이 지원·서식지 회복을 선택합니다. 포인트는 돌봄에 쓰는 자원입니다.

햇빛·물·공기·토양은 기존 종별 생산자 적합도에 반영되고 공기는 동물의 활동 속도에도 영향을 줍니다. 나쁜 환경에서는 생산자의 성장과 먹이 회복이 불리해져 소비자에게 이어집니다.

이전 저장의 나쁜 햇빛·공기는 그대로 복원합니다. 환경 패널의 **서식지 회복 — 8포인트**에서 한 요소를 보통으로 개선할 수 있습니다. 기존 75초 재사용 대기와 60초 생산자 회복 효과를 유지하고 비용·상태·대기는 관리 시스템이 검증합니다. 물·토양은 기존 ! 관리 흐름을 유지합니다. 날씨나 무작위 환경 악화는 아직 없습니다.

첫 발견·학습·? 조사는 최초 보상으로 포인트를 줍니다. 모든 최초 보상을 이미 받고 포인트까지 소진한 나쁜 환경 저장은 유료 회복이 막힐 수 있습니다. 이를 무료 조절이나 저장값 보정으로 감추지 않았으며 상세 한계와 후속 최소 수정안은 STAGE9_REPORT.md에 적었습니다.

## 자동 저장과 복원

같은 브라우저·같은 사이트에서 새로고침하거나 닫았다 다시 열면 숲의 주요 진행을 불러옵니다. 저장 여부는 아래 작은 문구로 표시합니다. 저장은 이 기기의 브라우저에만 남으며 서버로 전송하지 않습니다. 다른 기기/브라우저/호스트·포트에서는 공유되지 않습니다.

기존 저장 형식 `schemaVersion=7`과 key `eco-system:forest-save`를 유지합니다. 안내 확인 여부는 별도 UI 설정 `eco-system:forest-guide-seen`에만 기록하며 게임 진행/목표 기록을 중복 저장하지 않습니다.

생물·위치·성장·먹이량·배고픔, 환경, 카드, 활동, 발견, 포인트/보상, 관리/대기/효과, 최고 안정도와 클리어를 저장합니다. 먹이 추적 대상·열린 창·선택·이동 캐시는 저장하지 않고 안전하게 다시 구성합니다. 기록 전 💡 후보는 보존하고, 문제 알림은 실제 상태에서 다시 평가합니다.

닫아 둔 시간 동안 생태계가 진행되지 않습니다. 저장 당시의 관리 효과/대기 시간은 활성 시뮬레이션 시간을 기준으로 이어집니다. 미완료 30초 유지 도전은 불러올 때 0부터 시작합니다.

**숲 목표 → 처음부터 다시 하기**에서 확인하면 저장과 현재 실행 상태를 함께 초기화합니다. 취소하면 진행이 유지됩니다. 저장소 접근이 막히거나 용량 오류가 나도 게임은 실행되며 안내 문구를 표시합니다. 지원하지 않는 과거/미래 저장 형식은 임의 변환·덮어쓰기하지 않고 새로 시작하기 확인을 기다립니다.

## 실행·검사·작업 위치

원본: `C:\Users\User\Documents\GitHub\eco-system`. ZIP/복사본을 원본으로 사용하지 않습니다. 커밋·푸시는 사용자가 GitHub Desktop에서 진행합니다.

빌드나 서버 API가 필요하지 않습니다. 저장소 루트의 정적 HTTP 서버 또는 기존 GitHub Pages에서 실행합니다. 예: `python -m http.server 8081` 후 `http://127.0.0.1:8081/`. ES 모듈을 사용하므로 file:// 더블클릭 대신 HTTP 주소를 사용하세요.

순수 검사: `node --test tests/*.test.mjs`

브라우저 검사: tests의 browser/feeding/environment/events/management/activities/persistence/guidance.browser 검사 파일. Playwright/Edge가 필요하며 BASE_URL과 PLAYWRIGHT_MODULE로 환경을 지정합니다. 저장 전용 테스트는 실제 `/eco-system/` 하위 경로를 제공하는 정적 서버에서 실행합니다. 앱 실행에는 검사 도구가 필요하지 않습니다.

개발용 환경 비교 UI는 `js/dev/environment-tools.js`에 보존합니다. 일반 main.js는 이를 가져오지 않습니다. 자동 검사에서 `tests/fixtures.cjs`의 `useDeveloperEnvironment(page)`가 테스트 응답에만 명시적으로 연결합니다. 학생 화면 버튼이나 `?dev=true` 같은 주소로 활성화할 수 없습니다.

설계는 ARCHITECTURE.md, 검증은 QA.md, 이번 보고는 STAGE9_REPORT.md를 보세요. 과거 보고서는 당시 구현 기록입니다. 관리자 화면·로그인·원격 저장·강/바다·신규 이미지·분해 시뮬레이션은 없습니다. Galaxy Tab S5e 실기기 터치와 발열은 별도 확인이 필요합니다.
